# Plan 3: Hypothesis Evaluation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every hypothesis states, in parseable form:
- **Reach:** how many customers are affected, backed by its signals.
- **Confidence:** how certain we are that the target metric moves.
- **Validation path:** how it will be validated, routed by cost.

A script scores and ranks hypotheses with a pluggable framework (RICE by default), recommends a validation path, and keeps a generated board current. Experiments link back to the hypothesis they test.

**Architecture:**
- **Template:** v2 adds a header field table, `## Signals` (many-to-many with `SIG-` ids), `## Evaluation` (one row per framework factor, each with a Basis) and `## Validation plan`.
- **Canonical config:** `reference/hypothesis-scoring.yaml` names the active framework, its factor scales and the routing threshold. `reference/hypothesis-scoring.md` and `reference/validation-methods.md` explain them.
- **Code:** `scripts/hypotheses/` parses files, applies the framework (implemented in Python, never `eval`), computes evidence-backed reach from the signal store (Plan 2), recommends a validation path, and renders `product-development/product/PRDs/hypotheses-board.md`.
- **Checks:** a new integrity-check module enforces completeness, valid values, known metrics and signals, routing sanity, staleness and an up-to-date board.
- **Command:** `/hypothesis` drafts a hypothesis from signals.

**Tech Stack:** Python 3.12, PyYAML, pytest; `scripts/signalstore` from Plan 2.

**Spec:** the owner's stage 2–3 description (reach, confidence, how to validate; cheap → build and A/B test, complex → survey or prototype first); [gap analysis](../../../gap-analysis-product-loop-2026-11-03.md) §3 Stages 2–3; decision "pluggable, RICE default" in the [plans index](../2026-11-03-product-loop-plans-index.md).

## Global Constraints

- Hypothesis statuses, in lifecycle order: `proposed`, `prioritized`, `validating`, `validated`, `invalidated`, `in-prd`, `shipped`, `measured`, `parked`.
  - Active (ranked on the board): `proposed`, `prioritized`, `validating`.
  - Closed: everything else.
- Validation paths: `ab-test`, `prototype`, `survey`, `interviews`, `fake-door`, `data-analysis`.
- RICE factors, as written in the `## Evaluation` table's Factor column:

  | Factor | Scale |
  |---|---|
  | `Reach` | number > 0, customers per quarter |
  | `Impact` | one of `0.25`, `0.5`, `1`, `2`, `3` |
  | `Confidence` | integer percent 0–100, written with or without `%` |
  | `Effort` | number > 0, person-weeks covering validation plus build |

  Score = `Reach × Impact × (Confidence / 100) / Effort`, rounded to 1 decimal.
- ICE ships as the alternative: `Impact`, `Confidence` and `Ease`, each an integer 1–10. Score = product.
- A factor value of `?` means "not estimated yet": the hypothesis is unscored, never an error that crashes anything.
- Routing rule, default `cheap_effort_max_weeks: 1`:
  - Recommend `ab-test` only when Effort ≤ threshold **and** the target metric is instrumented.
  - Otherwise recommend `prototype`, listing `survey`, `interviews` and `fake-door` as alternatives.
  - The rule recommends; a human may choose differently. The check flags only `ab-test` chosen against the rule.
- "Instrumented metric" means a metric name in the `reference/metrics.md` table (bold and parenthetical abbreviation both accepted), or a `### ` heading in `product-development/analytics/metrics/**/*.md`. Plan 6 adds `metric-watch.yaml` names.
- The board is generated, carries no date, and starts with `<!-- generated by scripts/hypotheses/score.py; do not edit -->`.
- New `reference/` files need owner approval (ADR 0003).

## Review Focus

1. **Factor values written loosely** (`50 %`, `0,5`, `3 weeks`). Expected: `50 %` parses; `0,5` and `3 weeks` produce a `hyp-invalid-values` finding naming the factor, and the hypothesis is unscored. Pinned in Task 2 (`test_loose_values`).
2. **`Effort` of `0`.** Expected: invalid value, never a ZeroDivisionError. Pinned in Task 2 (`test_zero_effort_is_invalid`).
3. **Framework switched to ICE** while files hold RICE rows. Expected: each file gets a missing-factor finding, and the board lists it as unscored. Pinned in Task 3 (`test_framework_switch_degrades_gracefully`).
4. **A closed hypothesis** (`invalidated`, `measured`). Expected: not ranked, but listed in the board's "Closed" section with its Result. Pinned in Task 3 (`test_closed_hypotheses_are_listed_not_ranked`).
5. **A hypothesis citing a signal that was later archived.** Expected: still counted for reach, flagged as archived on the board. Pinned in Task 3 (`test_archived_signal_is_flagged`).

**Interfaces:**
- Produces:

```python
@dataclass
class Hypothesis:
    hyp_id: str; path: Path; status: str; target_metric: str; validation_path: str
    last_updated: str; prd: str; opportunity_ids: list[str]; signal_ids: list[str]
    factors: dict[str, str]          # raw cell text by Factor name
    bases: dict[str, str]
    result: str
    missing: list[str]               # header fields / sections absent

def hypothesis_files(repo_root: Path) -> list[Path]          # product-development/product/PRDs/**/*-hypothesis.md
def parse_hypothesis(path: Path) -> Hypothesis

@dataclass
class Score: value: float | None; errors: list[str]; unscored: list[str]   # unscored = factors that are "?"

def load_scoring_config(repo_root: Path) -> dict
def parse_factor(raw: str, spec: dict) -> float | None   # None for "?"; raises ValueError("<factor>: <why>") on invalid
def score(h: Hypothesis, config: dict) -> Score          # dispatch on config["framework"] to FRAMEWORKS
FRAMEWORKS: dict[str, Callable[[dict[str, float]], float]]   # {"rice": ..., "ice": ...}
```

`signal_ids` are collected with `SIGNAL_ID_IN_TEXT` from `scripts/signalstore/store.py`.

Board layout:

- Hypothesis cells link to the file. Archived signals render as `SIG-007 (archived)`.

**Interfaces:**
- Produces these check ids (key = `hyp_id` unless stated):

  | Check id | Finding |
  |---|---|
  | `hyp-missing-fields` | Any `missing`, or a factor of the active framework absent from `## Evaluation` |
  | `hyp-invalid-values` | Bad status, path or factor value; message from `ValueError` |
  | `hyp-unknown-metric` | Target metric not instrumented |
  | `hyp-unknown-signal` | A `SIG-` id not in `signals.csv` |

  | `hyp-board-stale` | Rendered board ≠ file on disk; key `hypotheses-board` |
  | `experiment-unknown-hypothesis` | An experiment's `**Hypothesis**` header cites a missing `HYP-` id; key = experiment path |
