## Performance and Large Datasets (18:45 - 29:00)

**Hannah:** Let's talk about the contract catalog performance issues you flagged in your support ticket last week.

**Leo Martinez:** So we built a contract management tool in example_product for our rights and licensing catalog. Agreements, renewal dates, royalty terms, rights holders — the whole thing. We need virtual scrolling and server-side filtering. The generated code does client-side filtering by default, which obviously doesn't scale.

**Sam Chen:** That's a fair criticism. Right now the generated code loads all data into memory and filters client-side. For the dataset sizes most of our users work with, that's fine. But 12K records is a different beast. There are two things we can do. Short-term, I can help you refactor the existing workflow to add pagination and server-side filtering. **Sam:** Agreed. I'm going to look into adding virtual scrolling as a default pattern when the data source exceeds a configurable threshold. It's the kind of thing the platform should handle automatically.

**Hannah:** Leo, would you be willing to share the contract catalog workflow with Sam so he can use it as a test case for the performance work?

**Leo:** Yeah, I can do that. I'll share the workflow tomorrow.
