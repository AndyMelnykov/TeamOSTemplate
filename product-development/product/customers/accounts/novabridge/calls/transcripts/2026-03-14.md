## Multi-Step Workflow Reliability (12:00 - 22:00)

**Hannah Stulberg:** James, let's dig into the multi-step workflow topic. You've mentioned this before — what's the current state from your perspective?

**James Okoro:** When I automate a single-form intake, example_product nails it almost every time. But the moment I need a workflow spanning 3+ document types with shared applicant data and conditional routing, the success rate drops significantly. I've learned to break things into phases — set up the intake fields first, then add routing, then wire in the shared data. But Amara shouldn't have to learn those tricks to be productive.

**Jordan Kim:** Can you give me a specific example of a failure case?

**James Okoro:** Sure. Last week I described an account-opening workflow with three intake steps — a government ID upload, a proof-of-address upload, and a KYC questionnaire — using conditional routing for manual review and a shared applicant record across all three. example_product built all three intake steps, which was great. But the routing configuration was wrong — it used an outdated approval-step syntax. The shared applicant record was defined but never wired to the questionnaire step. And the field mappings between steps were inconsistent — some referenced fields directly, some used aliases that weren't configured.

**Jordan Kim:** Was that with the default KYC template or a custom configuration?

**James Okoro:** Default KYC template. And here's the thing — when I rebuilt each step individually and described the field mappings explicitly, it worked fine. The model clearly knows how to write correct routing logic and shared-record logic. It's the orchestration across steps that breaks down.

**Jordan Kim:** That's a really precise diagnosis. The multi-step orchestration layer is something we're actively improving. The model can handle individual step extraction well, but maintaining consistency across step boundaries — field mappings, shared record definitions, routing wiring — that's the hard problem we're working on.

**James Okoro:** Here's what I want to see — I describe an account-opening workflow with shared applicant data and a document verification layer, and example_product builds all the steps in one pass with the correct field mappings and routing. That's the promise. We're not there yet, but the foundation is solid.

**Jordan Kim:** That's exactly the target state. Would you be interested in joining our beta program for multi-step workflow improvements? We'd love to have a power user like you testing early builds.

**James Okoro:** Definitely. Sign me up.

**Hannah Stulberg:** We'll get you added this week.
