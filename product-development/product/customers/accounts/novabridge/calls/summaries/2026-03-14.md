## Company Context
NovaBridge is a fintech company with a 10-person engineering team running 9 active workflows on example_product, automating account-opening and KYC document processing. James Okoro is the account champion and a power user who has developed effective workarounds for current limitations. Amara Nwosu recently joined the team and is ramping up on example_product as a new user.

## Key Themes
### 1. Multi-Step Workflow Reliability (Pain Point — P0)
James described a significant drop in extraction success rate when moving from single-form intake to multi-step workflows. Single-document intake automates correctly roughly 85%+ of the time, but workflows with 3+ document types involving shared applicant data and conditional approval routing drop to around 60% success. He's developed a phased build workflow — set up field extraction first, then routing, then shared data — but acknowledged this is a workaround, not a solution: "When I automate a single-form intake, example_product nails it almost every time. But the moment I need a workflow spanning 3+ document types with shared applicant data and conditional routing, the success rate drops significantly." Jordan asked detailed follow-up questions about which document types and routing patterns fail most often. James noted government-ID plus proof-of-address combinations with branching approval steps are the most problematic, while single-document KYC workflows fare slightly better.

### 2. Onboarding Documentation Gaps (Pain Point — P1)
Amara shared her experience as a brand-new example_product user. She spent two full days trying to figure out multi-step workflow setup because the documentation jumps from a single-field extraction example directly to advanced configuration with no intermediate guidance: "The docs show a single-field extraction example and then jump straight to advanced configuration. There's nothing in between for someone who's new to AI-powered document automation." Jordan noted we've heard similar feedback from other new users and that a docs overhaul is in progress. Amara specifically requested a guided tutorial that walks through building a 2-3 step account-opening workflow, start to finish.

### 3. Workflow Version History (Pain Point — P1)
James raised workflow version history as a recurring ask. His team currently exports workflow configurations and manually tracks changes in a shared spreadsheet, which creates friction and makes it hard to tell what routing logic changed and when. He wants native version history so example_product workflows keep an auditable change log. Jordan confirmed this is on the roadmap but didn't commit to a timeline.

### 4. Vision for Multi-Document Workflows (Positive)
Despite the current limitations, James expressed strong confidence in example_product's direction: "Here's what I want to see — I describe an account-opening workflow with shared applicant data and a document verification layer, and example_product builds all the steps in one pass with the correct routing and field mapping. That's the promise. We're not there yet, but the foundation is solid." He's willing to participate in beta testing for multi-step workflow improvements.
